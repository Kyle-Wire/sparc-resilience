# 2026-05-22 — CU-10a/b/c: Multi-GPU DDP Infrastructure

## Summary

Completed CU-10a (DDP spawn entrypoint), CU-10b (EWC Fisher all_reduce), and CU-10c (OT alignment all_reduce), implementing multi-GPU fold-parallel training infrastructure gated behind `HardwareProfile.ddp_enabled` (default `False`).

## Changes

### `sparc/run/v2_neural_training.py`

**Module-level helpers (CU-10a):**
- Added `_TRUNK_KEYS: frozenset[str]` constant — promoted from local variable in `train_neural_meta` so `_exec_cv_fold` and `_ddp_fold_worker` can reference it without closure capture.
- Added `_init_ddp_process_group(rank, world_size, backend)` — initialises NCCL process group with gloo fallback; uses `env://` init method for `torchrun` / `spawn` compatibility.
- Added `_destroy_ddp_process_group()` — safe teardown called in `_ddp_fold_worker` finally block.
- Added `_ddp_fold_worker(rank, world_size, fold_assignments, shared_state, oof_preds_shared, oof_std_shared)` — module-level worker spawned by `torch.multiprocessing.spawn`; moves tensors to per-rank GPU, calls `_exec_cv_fold`, writes results to shared-memory tensors.
- Added `_exec_cv_fold(fold_idx, train_idx, test_idx, ss, device)` — extracted entire ~677-line fold body from `train_neural_meta` into a module-level function; accepts all outer-scope state via the `ss` dict; returns `(test_idx, oof_preds_fold, oof_std_fold)` instead of writing to outer arrays; safe for `torch.multiprocessing.spawn`.

**`train_neural_meta` changes:**
- Added `pr_pretrain_epochs = int(pr_cfg.get("pretrain_epochs", 0))` near `pr_cfg` extraction.
- Removed local `_TRUNK_KEYS = {...}` (now module-level).
- Inserted `_fold_shared` dict construction (76 keys) immediately before fold loop.
- Inserted DDP detection block: reads `ddp_enabled` from `HardwareProfile`, computes `_gpu_count_ddp`, sets `_use_ddp = _ddp_enabled and _gpu_count_ddp > 1 and len(folds) > 1`.
- Replaced 677-line fold body loop with:
  - **DDP path**: moves tensors to CPU shared memory, calls `torch.multiprocessing.spawn(_ddp_fold_worker, ...)`, collects results from shared-memory tensors.
  - **Sequential path**: iterates folds, calls `_exec_cv_fold`, writes `oof_preds`/`oof_std`.

### `sparc/config/hardware_profile.py`

- Added `ddp_enabled: bool = False` field to `HardwareProfile` dataclass.
- Added `"ddp_enabled"` to `_OVERRIDABLE_FIELDS` tuple.
- Updated `_coerce_overrides` bool branch to include `"ddp_enabled"`.

### `sparc/training/ewc.py` (CU-10b)

if dist.is_initialized():
    dist.all_reduce(n_samples_t, op=dist.ReduceOp.SUM)

## Design decisions

- **Sequential path unchanged**: `_use_ddp` is `False` by default (requires explicit opt-in via `ddp_enabled: true` in config + multi-GPU machine). No behaviour change for existing single-GPU runs.
- **Shared state dict (`_fold_shared`)**: 76 items covering all arch hyperparams, training params, JEPA config, EWC/OT config, device flags. Avoids closure capture so the fold body is spawn-safe.
- **Tensor sharing in DDP path**: tensors moved to CPU + `share_memory_()` before `spawn`; each worker calls `.to(device)` inside `_ddp_fold_worker`. The sequential path is a no-op check (tensors already on device).
- **`ss` naming**: avoids collision with `for s in surrogates.values()` loop variable inside `_exec_cv_fold`.
