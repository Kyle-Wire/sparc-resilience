## Design Decisions (resolved via grill)

### A — JEPA → Stage 3 Causal Integration

**Q: Replace or residualize?**
→ **Residualize.** Replace loses interpretability (256-d anonymous DAG). Residualize keeps feature names, only removes spatial confounding structure.

**Q: Which residualization target?**
→ **(i) Spatial autocorrelation removal** from treatment features + **(ii) DML nuisance augmentation** — staged, both.

**Q: Where does the residualizer live architecturally?**
→ **Option C: thin `SpatialResidualizer` pre-processing stage** between Stage 2 and Stage 3. Keeps Stage 3 data-only. Independently testable.

**Q: What probe model on the trunk?**
→ The user surfaced a better insight: **Stage 2 `oof_preds` are the free win for `model_y`**. The trunk probe applies to `model_t` (treatment nuisance) only. Two separate items:
- **JD-1**: Thread `oof_preds` into Stage 3 as pre-computed `model_y` — no JEPA required.
- **JD-2**: JEPA trunk → PCA-16 → Ridge probe → residualized treatment features.

**Q: Hard or soft dependency on JEPA?**
→ **Graceful degradation**: if no JEPA trunk in artifact store, `SpatialResidualizer` is a no-op pass-through. Log: `[INFO] No JEPA trunk found — skipping spatial residualization`.

**Q: Enable JEPA by default?**
→ **Yes, globally** (`jepa.enable: true` in schema). User is sole operator; 25–35% training cost accepted in exchange for trunk availability for the residualizer.

---

### B — Multi-Step Latent Rollout (World Model)

**Q: Forward simulation or planning optimizer?**
→ **Both, sequenced.** Start with forward simulation (A), build planning on top (B → full C). Planning hooks into existing `CausalBandit` roadmap stub.

**Q: Recurrent latent chain vs. re-encode?**
→ **Both**: (A) pure latent chain capped at 5 steps; (B) re-encode with physics cascade table. Same API, `mode="latent"` vs `mode="reencode"`.

**Q: Feature perturbation model scope?**
→ **Physics cascade table** (B): config-driven YAML `treatment_cascades` per template (e.g., `tree_planting: {ndvi: +0.8, albedo: -0.05}`). Learned cascade model deferred to a future item.

**Q: API shape?**
→ Single call: `multi_step_latent_rollout(..., actions=[(treatment, delta_x, delta_t), ...], mode="latent"|"reencode")` → `MultiStepRolloutResult(steps: list[LatentRolloutResult], final: LatentRolloutResult)`.

## Grounded Directions → Backlog Items

### JD-1: Stage 2 OOF as DML `model_y` nuisance (free win)
**Gap:** `_fit_edge_dml()` in `counterfactual_engine.py` refits HGB for `model_y` from scratch per edge. Stage 2 `oof_preds` are strictly better (full ensemble + spatial CV) and already computed.
**Roadmap ref:** Phase 5 — Causal Inference Leadership
**Method:** Frisch-Waugh residualization with pre-computed oracle `ĝ(X)` — no new theory, just pass the artefact through.
**Implementation:** Thread `oof_preds` via artifact store into `v2_bayesian_causal.py`; pass as optional `precomputed_outcome_preds` to `_fit_edge_dml`; when present, skip `model_y.fit()` and compute `Ỹ = Y - precomputed_outcome_preds` directly. Config flag `causal.use_stage2_outcome_nuisance: true` (default true).
**Complexity:** low (~30 lines, 2 files)

### JD-2: SpatialResidualizer — JEPA trunk → treatment feature deconfounding
**Gap:** Treatment features entering Stage 3 carry spatial autocorrelation structure that biases DML's `model_t` nuisance. JEPA trunk has learned physics-consistent spatial representations but they never reach Stage 3.
**Roadmap ref:** Phase 5 + Phase 1.3 synergy
**Method:** Spatial residualization via low-rank linear probe on EMA trunk: PCA trunk embedding to 16 dims → per-feature Ridge regression → residuals. Schölkopf et al. identifiable causal representations — using a learned spatial representation to remove structured confounding before CI testing.
**Implementation:** New `sparc/causal/spatial_residualizer.py` — `SpatialResidualizer.fit_transform(df, trunk, device)`. Loads trunk from artifact store (`jepa_trunk_state_dict`), calls `model.encode()`, PCA-16, Ridge per treatment column, writes `{col}_resid` columns + originals. Graceful no-op if no trunk. Wired into `v2_bayesian_causal.py` as pre-step gated by `causal.use_spatial_residuals: true`.
**Complexity:** medium (~80 lines, 2 files + new module)

### JD-3: `jepa.enable: true` schema default
**Gap:** Schema default is `false`; `SpatialResidualizer` degrades to no-op for all existing runs.
**Implementation:** Change `"default": false` → `"default": true` in `project_schema.json` under `jepa.enable`. Update description string.
**Complexity:** low (1 line)

### JD-4: Multi-step latent rollout — recurrent latent chain
**Gap:** `latent_rollout.py` is single-step only. No compounded intervention simulation.
**Method:** Recurrent JEPA world model — chain `h_{t+1} = predictor(h_t, action_t)`, decode only at final step. V-JEPA 2-AC extended to sequences. Hard cap: `max_steps=5`.
**Implementation:** Extend `sparc/inference/latent_rollout.py` with `multi_step_latent_rollout(..., actions, mode="latent", max_steps=5)` → `MultiStepRolloutResult`. Each step accumulates into `steps: list[LatentRolloutResult]`. Final `h_T` decoded once.
**Complexity:** medium (~60 lines, 1 file + new dataclass)

### JD-5: Multi-step re-encode with physics cascade table
**Gap:** Re-encode mode requires knowing how intervention A affects ALL correlated features (not just the target feature), for physically plausible re-encoding.
**Method:** Physics cascade table per domain template: `caps.yml` key `treatment_cascades` maps `(treatment) → {feature: scale_factor}`. Applies additive perturbation to DataFrame, then re-encodes via trunk for each step.
**Implementation:** New `sparc/inference/feature_perturbation.py` — `PhysicsCascade.apply(df, treatment, delta_x) → df_perturbed` reading from `caps.yml`. `multi_step_latent_rollout(..., mode="reencode")` calls cascade → `model.encode()` → predictor → decode per step. Add `treatment_cascades` section to all 13 domain templates.
**Complexity:** medium (~90 lines across 3 files + template updates)
