### Direction 2 — Fix replay loss interface (1.1-b)

**Gap:** `compute_replay_loss()` in `sparc/training/replay.py` calls `model(**{"features": X})`. `SPARCMetaLearner.forward()` requires `(base_preds, physics_feats, X_spatial, coords, knn_index, alpha)`. The model cannot accept `features=X`. This is a permanent interface mismatch — the function is completely unwired as a result.

**Roadmap reference:** Phase 1.1 — EWC + Replay (SPARC_Future_Roadmap.md, SPARC_Integration_Status.md Gap 1). Last unresolved Phase 1 item.

**Academic method:** Experience replay / episodic memory (Rolnick et al. 2019 *Experience Replay for Continual Learning*). The coreset is already selected per-city by `CoresetSelector`; the gap is only the forward pass.

**Implementation sketch (redesign `compute_replay_loss`):**

```python
def compute_replay_loss(
    model: nn.Module,
    coreset: dict,  # from CoresetSelector — has 'X', 'y', 'coords'
    # Pre-built KNN/spatial encodings for the coreset
    coreset_spatial: torch.Tensor,
    coreset_knn: torch.Tensor,
    coreset_alpha: torch.Tensor,
    coreset_base_preds: torch.Tensor,  # from saved surrogate outputs
) -> torch.Tensor:
    T_pred, _, _ = model(
        base_preds=coreset_base_preds,
        physics_feats=coreset["X"],
        X_spatial=coreset_spatial,
        coords=coreset["coords"],
        knn_index=coreset_knn,
        alpha=coreset_alpha,
    )
    return nn.functional.mse_loss(T_pred.squeeze(), coreset["y"])
```

The `CityRegistry` coreset dict needs to be extended to store pre-built spatial encodings and saved surrogate predictions alongside `X`, `y`, `coords`. These can be computed once at the end of each city's training run (in `train_continual()`) and cached.

**Success criterion:** Loss log shows non-zero `replay_loss > 0` during second-city training; Providence R² does not degrade after Boston.

### Direction 4 — `few_shot_predict()` implementation (Phase 4.2)

**Gap:** `sparc/inference/few_shot.py::few_shot_predict()` is stubbed with `raise NotImplementedError`. The architecture is designed: freeze the trunk, fine-tune only the CityHead (2 linear layers) on 3–10 ground observations for 50 epochs. The trunk checkpoint is available via `CityRegistry`.

**Roadmap reference:** Phase 4.2 — Few-Shot Fine-Tuning (SPARC_Future_Roadmap.md)

**Academic method:** Meta-learning / Model-Agnostic Meta-Learning (MAML, Finn et al. 2017). The SharedTrunk / CityHead split IS MAML's outer/inner loop architecture. With a frozen trunk, fine-tuning the city adapter on 3–10 examples is computationally cheap (50 epochs, ~1 s on CPU) and directly implements the MAML inner loop.

**Implementation sketch:**

```python
def few_shot_predict(feature_set: SatelliteFeatureSet,
                     observations: list[GroundObservation],
                     trunk_checkpoint: Path) -> ZeroShotPrediction:
    model = SPARCMetaLearner.load_trunk(trunk_checkpoint)
    model.freeze_trunk()
    city_optimizer = AdamW(model.city_head_parameters(), lr=1e-3)
    for epoch in range(50):
        loss = mse(model(obs.features), obs.target)
        city_optimizer.step()
    return model.predict_with_uncertainty(feature_set.spatial_grid)
```

**Success criterion:** With 5 ground observations, few-shot R² > cold-start R² on held-out grid; uncertainty bands widen in areas far from observations.

## Blue-Sky Ideas

### Latent Diffusion for Posterior Scenario Sampling

**Source field:** Score-based generative models (Song et al. 2021 *Score-Based Generative Modeling*; Ho et al. 2020 DDPM) × `sparc/models/neural_meta.py` trunk latent space × `sparc/interventions/scenario_simulator.py`

**Core idea:** The JEPA trunk encodes spatial physics observations into a latent field h(x) ∈ ℝ^{hidden_dim}. Currently the scenario simulator produces a single point-estimate counterfactual map. A lightweight DDPM conditioned on the physics features — 3 denoising UNet layers over the N×hidden_dim trunk latent field — would let SPARC *sample* a posterior over plausible counterfactual scenarios. Each sample is a spatially coherent field that satisfies the PDE constraints implicit in the trunk's training. The result: instead of "cooling estimate: −1.2°C", SPARC reports "posterior mean −1.2°C, 90% credible interval [−2.1°C, −0.4°C]" with the full distribution available for risk analysis. 

The JEPA EMA trunk produces natural training targets: given an observed h(x), add noise, train a UNet to denoise conditioned on physics features. The existing `jepa_loss.py` VICReg variance/covariance terms already regularize the latent space to be diffusion-friendly (non-collapsed, near-Gaussian marginals).

**Potential impact:** new capability (full posterior over scenarios — a major differentiator for insurance/planning use cases), methodological (first physics-constrained diffusion model for spatial urban intervention scenarios), interpretability (uncertainty maps for every scenario, not just point estimates)

**Relevant SPARC modules:** `sparc/models/neural_meta.py` (`EMATrunk.encode_target` as target encoder), `sparc/training/jepa_loss.py` (latent regularization), `sparc/interventions/scenario_simulator.py` (scenario conditioning), `sparc/physics/pde_loss.py` (physics constraint)

### Causal Bandits for Sequential Intervention Design

**Source field:** Multi-armed bandits with Thompson sampling (Thompson 1933; Russo et al. 2018) × `sparc/decision/policy_learning.py` (`EmpiricalWelfareMaximizer`) × `sparc/causal/spatial_cate.py` (CATE posteriors) × `sparc/interventions/scenario_simulator.py`

**Core idea:** `EmpiricalWelfareMaximizer` learns a one-shot policy: given AIPW scores, choose treatments to maximize welfare. But urban heat interventions are sequential: planting canopy in year 1 changes the effective treatment response for impervious reduction in year 2 (interaction effects, budget carry-over). 

A Thompson sampling bandit treats each intervention type (canopy ×, albedo ×, impervious ×) as a bandit arm. The posterior over arm rewards is the CATE GP surface from `spatial_cate.py` — a Matérn GP already fitted with Stage 0 covariance parameters. At each "decision round" (year), the bandit samples from the CATE posterior, executes the highest-value arm, and updates the posterior with the observed spatial field change (simulated via `scenario_simulator.py` as a cheap oracle). After T rounds, the optimal multi-year intervention sequence is revealed.

The existing infrastructure makes this nearly free to prototype: `SpatialCATEEstimator.fit_gp_surface()` is the posterior; `scenario_simulator.py` is the oracle; `EmpiricalWelfareMaximizer` becomes the one-shot baseline to beat.

**Potential impact:** new capability (optimal multi-year intervention planning under uncertainty — clinically relevant for municipal climate adaptation), methodological (bridges causal inference and sequential decision-making, publishable), performance (provably sublinear regret vs. greedy one-shot allocation)

**Relevant SPARC modules:** `sparc/causal/spatial_cate.py` (`CATEGPSurface`), `sparc/decision/policy_learning.py` (`EmpiricalWelfareMaximizer`), `sparc/interventions/scenario_simulator.py`, `sparc/causal/sensitivity.py` (E-values as risk bounds)
