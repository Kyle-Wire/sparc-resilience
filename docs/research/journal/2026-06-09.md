## Grounded Directions

### Direction 1 — `CollectSession` round-trip persistence + server restart recovery
**Gap:** `CollectSession.save()` and `.load()` are implemented but never called on server startup.
The FastAPI server always resets `_collect_session = CollectSession()` on restart — any in-progress
collection is lost. A user who lost connection mid-collection must restart all fetches.
**Roadmap ref:** Phase 3.1 (Satellite + Climate Ingestion pipeline resilience)
**Method:** Add a `GET /collect/session` and `POST /collect/session/restore` endpoint pair.
`GET` returns the JSON sidecar if it exists (`CollectSession.save()` now writes it at
`/collect/build` time). `POST /collect/session/restore` loads from the JSON path provided in
the body and rehydrates `_collect_session` with boundary metadata and anchor_dates.
**Minimal implementation:**
- ~20 lines in `app.py`: two new routes + a `_SIDECAR_PATH` constant
- `CollectSession.load()` already handles partial rehydration (fishnet is None; user re-fetches)
- Guard with a session-state enum: `EMPTY | HAS_BOUNDARY | HAS_FETCHES | BUILT`
**Files:** `sparc/server/app.py` (+2 routes), `sparc/data/collect/session.py` (no change needed)

### Direction 2 — `zero_shot_predict()` registry path implementation
**Gap:** `sparc/inference/zero_shot.py` line 59 raises `NotImplementedError` when
`registry_path is not None`. The trunk loading path is the gating prerequisite for Phase 4.
**Roadmap ref:** Phase 4 Zero-Shot Inference

Then in `zero_shot.py`, replace the `raise NotImplementedError` with the above call.
**Minimal implementation:** ~50 lines across 2 files.
**Files:** `sparc/registry/city_registry.py` (new method), `sparc/inference/zero_shot.py` (remove NotImplementedError)

### Direction 4 — Energy-Based Coreset Selection
**Gap:** `CoresetSelector._greedy_kmedoids()` is gradient-free (no awareness of model failure modes).
Coresets selected near feature-space centroids systematically miss OOD tail behaviors — the
precisely wrong anti-forgetting signal.
**Roadmap ref:** Phase 1.6 / Phase 2 Continual Learning Quality
**Method:** Energy-based selector: `E(z) = ‖model(z) − y‖²`. Langevin dynamics:
`z_{t+1} = z_t − η∇_z E(z_t) + √(2ησ) ε`. Run L=20 Langevin steps starting from K-medoid
seeds, accept/reject via Metropolis. This yields coresets concentrated near the model's
current failure modes.
**Minimal implementation:** ~70 lines in `sparc/training/replay.py` — new `select_energy_based_coreset()` function alongside the existing `CoresetSelector`.
**Files:** `sparc/training/replay.py`
**Dependencies:** `model.forward()` with `requires_grad=True` on inputs — already works via PyTorch autograd.
**Success criterion:** Energy-based coresets have higher OOF loss on old-city data than K-medoid
coresets (measurable in multi-city continual test).

### Direction 5 — Causal Transportability Module
**Gap:** `sparc/causal/transportability.py` does not exist. This is the formal basis for zero-shot
causal inference in Phase 4 — transporting ATE estimates from a trained source city to an unseen
target city without ground-truth labels.
**Roadmap ref:** Phase 4 Zero-Shot Inference + Phase 5 Causal Inference Leadership
**Method:** Bareinboim & Pearl (2014) transport formula:
`ATE_target = Σ_z E_source[Y(t)|Z=z] · P_target(Z=z)`
where Z = selection variables (climate zone, land cover from `SatelliteFeatureSet`).
S-admissibility check for identifiability. Falls back to source ATE with caution flag when
not identifiable.
**Minimal implementation:** ~130 lines in new `sparc/causal/transportability.py`
**Files:** New `sparc/causal/transportability.py`; optional call in `v2_bayesian_causal.py`
**Success criterion:** Transports ATE within 5% of ground truth on 2-city synthetic test.

## Blue-Sky Ideas

### Idea 1 — Spatial Foundation Model via Physics-Guided Mask Token Pretraining
**Source field:** Vision Foundation Models — MAE (He et al. 2022, *Masked Autoencoders*), DINOv2 (Oquab et al. 2023)
**SPARC connection:** The 30m fishnet is a 2D spatial "image" where each pixel = one cell with
physics-feature channels. The SIREN trunk is already a continuous spatial function. Extension:
mask 50–75% of cells and pretrain the trunk to reconstruct their physics features conditioned
on context cells — a spatial MAE. Unlike JEPA (which aligns latent representations), spatial MAE
learns to reconstruct physically-plausible spatial fields in input space. The novel claim:
using PDE consistency loss on the reconstructed pixels forces the trunk to learn
physically-plausible spatial inpainting — not just statistical correlation.
**Potential payoff:** Zero-shot domain adaptation — given Sentinel-2 imagery for an unseen city,
the foundation model fills in CAPA/ERA5 features for masked regions, bootstrapping physics
features from imagery alone. This would formally close the Phase 4 data requirement gap.
**Existing SPARC infrastructure:**
- `sparc/training/jepa_loss.py`: `spatial_patch_mask()` — spatial mask generation already exists
- `sparc/physics/pde_loss.py`: reconstruction consistency can be enforced via PDE residuals
- `sparc/models/neural_meta.py`: `EMATrunk` momentum encoder handles EMA targets

### Idea 2 — Geometric Deep Learning on Road Network Graph for Urban Heat Propagation
**Source field:** Graph Neural Networks on urban graphs (Kipf & Welling 2017 GCN; Velickovic et al. 2018 GAT) × Urban heat island topology research (Oke et al. 2017)
**SPARC connection:** Urban heat propagates along roads (advection from surface heating and traffic).
SPARC currently uses a regular 30m Cartesian grid. A complementary representation on the road network graph — where edges encode road orientation and canyon aspect ratio — would capture the *directional* heat transport that the regular Laplacian misses. The `ProcessRateNet` α(x) field could be conditioned on road-graph node features (street width, orientation, surface albedo). `OSMnx` provides road network extraction from OSM; the existing fishnet joins to road segments via spatial join.
**Potential payoff:** Better LST prediction in canyon-dominated urban cores; road-network conditioning as a physics-grounded covariate that no existing spatial ML tool uses. Publishable as a "physics-informed road graph UHI model" result.
**Existing infrastructure:** `sparc/physics/pde_operators.py` (graph operators); `sparc/models/spatial_attention.py` (attention over arbitrary spatial graphs); OSMnx available in geospatial Python ecosystem.
