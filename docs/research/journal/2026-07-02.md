# Research Session — 2026-07-02

## Implementation Note — D1: Extract preprocessing pipeline to sparc/data/preprocessing.py

- **Files changed:**
  - `sparc/data/preprocessing.py` (new — 165 lines)
  - `sparc/server/routes/data.py` (refactored `/data/preprocess` handler: 128-line inline `_generate()` → 35-line thin wrapper)
  - `tests/test_server_route_modules.py` (appended `TestPreprocessingPipeline` — 4 new tests)

- **What was done:** Created `sparc/data/preprocessing.py` exposing a `run_pipeline(df, config, _result_ref=None)` synchronous generator that yields 9 step-result dicts (Ingest CSV → Reproject CRS → Deduplicate coords → Impute missing → Derive features → Standardise → Spatial block split → Write cached arrow → `__done__`). Each dict carries `step`, `done`, `rows`, `sha` keys. Filesystem side-effects (Welford scaler save, parquet cache write, versioning) are handled inside `run_pipeline` when `config["paths"]["project_root"]` is present, guarded by `try/except`. The route's `_generate()` became a thin async wrapper: it calls `run_pipeline`, formats each result dict as `data: <json>\n\n` SSE, emits the change-detection notice before the first step, and updates `state.data` via `_result_ref["df"]` after the generator is exhausted.

- **Tests:** 242 passed, 1 intentional failure (`TestDataRouter::test_has_upload_route`) — net +4 tests from the new `TestPreprocessingPipeline` class; all pre-existing tests unchanged.

- **What was learned:** Python generators cannot propagate their `return` value through a `for`-loop (or inside an async generator, where `StopIteration` is silently swallowed). The `_result_ref` mutable dict pattern is the lightest-weight way to expose the final transformed DataFrame from a sync generator to its async caller without changing the public dict-yield interface or introducing a second pass.
