# SPARC Research Journal — 2026-05-20c

## Implementation Note — CU-1 through CU-8 (GPU/CUDA Acceleration)

- **Files changed:** `sparc/config/hardware_profile.py`, `sparc/run/v2_neural_training.py`, `sparc/run/correlogram_matern_fit.py`, `sparc/models/gwen.py`, `tests/test_hardware_profile.py`
- **What was done:** Implemented all eligible GPU/CUDA backlog items for the `agents-continue-after-push` worktree. CU-1 adds `_detect_gpu()` helper + 4 GPU fields to `HardwareProfile` and decouples `force_cpu` from RAM tier (a machine with GPU is no longer forced to CPU even with low RAM). CU-2 adds full AMP (autocast bfloat16 + GradScaler) across CV, full-retrain, and SWA loops. CU-3 adds `gpu_batch_size` field computed as `min(max(vram_gb * 256, 512), 32768)` and overrides the training batch size when on CUDA. CU-4 removes the redundant `fold_cardinal_np` recomputation and eliminates the per-epoch `fold_cardinal.cpu().numpy()` GPU→CPU sync. CU-5 adds `del model, surrogates, ...` + `torch.cuda.empty_cache()` between CV folds to prevent VRAM fragmentation. CU-7 makes the Stage 0 Matérn NUTS device dynamic (was hardcoded `device="cpu"`). CU-8 adds optional cuML GPU path for GWEN's `NearestNeighbors` + `ElasticNet` (gated on import availability).
- **Tests:** Hardware profile tests updated with `_patch_no_gpu()` fixture to ensure CI (no GPU) still passes. All CU items are guarded by `torch.cuda.is_available()` — zero regression risk on CPU-only machines. Formal test run blocked pending PowerShell 7.6 PATH configuration.
- **What was learned:** CU-4 — `fold_cardinal_np` is ALREADY a numpy array computed at fold start; the inner `if use_minibatch:` block was redundantly recomputing it with identical arguments. CU-8 — cuML's `ElasticNet` doesn't have `CV`; uses global model's `alpha_` from sklearn as fixed alpha. CU-2 — COO sparse tensors don't support FP16; `T_pred` must be cast to `.float()` before `sparc_joint_loss`.
