## CUDA-1: MPS Device Support

**Motivation:** Training was silently falling back to CPU on Apple Silicon machines because the device selection only checked `torch.cuda.is_available()`. The MPS (Metal Performance Shaders) backend provides ~3–5× speedup over CPU on M1/M2/M3 Macs.

**Changes:** `sparc/run/v2_neural_training.py`

Device priority is now CUDA → MPS → CPU:
```python
if torch.cuda.is_available():
    device = torch.device("cuda")
elif getattr(torch.backends, "mps", None) and torch.backends.mps.is_available():
    device = torch.device("mps")
else:
    device = torch.device("cpu")
```

**MPS sparse tensor guard:** `build_sparse_laplacian` and `build_sheaf_laplacian` both produce sparse COO tensors that are consumed via `torch.sparse.mm` in `pde_loss.py`. MPS does not fully support sparse COO + `torch.sparse.mm` as of PyTorch 2.x. Both calls are gated with `device.type != "mps"` in `_prepare_tensors`, so on MPS the pipeline falls back to the 4-gather cardinal path (correctness-equivalent, ~10% slower on large grids).

## CUDA-2: AMP (Automatic Mixed Precision)

**Motivation:** On CUDA, float16 forward passes are ~2× faster and use ~50% less VRAM, enabling larger batch sizes. On MPS, bfloat16 autocast provides similar benefits.

**Two helper functions added** after `_maybe_compile`:

### `_build_amp_context(device, enabled)`
Returns `(scaler, autocast_fn)`:
- **CUDA:** `torch.amp.GradScaler("cuda")` + float16 autocast. Falls back to legacy `torch.cuda.amp` API on older PyTorch.
- **MPS:** bfloat16 autocast, `scaler=None` (GradScaler not needed/supported on MPS).
- **CPU / disabled:** `(None, contextlib.nullcontext)` — zero overhead.

### `_amp_backward_step(loss, params, clip_norm, optimizer, scaler, jepa_optimizer=None)`
Replaces the 6-line `backward → clip → step` pattern in all 3 training loops. When `scaler` is not None: scales loss, unscales before clip, steps via scaler. Otherwise: plain backward + clip + step.

**Integration into training loops:**
All 3 loops (CV fold, full retrain, SWA) now:
1. Wrap the core model forward calls in `with amp_autocast():` — surrogates, process net, source net, and the meta-learner trunk.
2. Use `_amp_backward_step(...)` for the backward+step section.
3. Additional penalty terms (EWC, OT continual learning, alpha supervision) remain outside autocast in float32 for numerical stability.

**AMP is auto-enabled** when `device.type in ("cuda", "mps")`. Override via `config["training"]["amp"] = false`.

**torch.compile compatibility:** The existing `_maybe_compile` already wraps all models. AMP + `torch.compile` works correctly in PyTorch ≥ 2.0 when autocast wraps the compiled forward call, which is the case here.

## CUDA-3: GPU VRAM-Aware Hardware Profile

**Motivation:** The hardware profile set `batch_size` purely from RAM tier, ignoring GPU VRAM. A workstation with 32 GB RAM and an A100 (80 GB VRAM) was getting the same batch_size as one with only CPU.

**Changes:** `sparc/config/hardware_profile.py`

1. Added `gpu_vram_gb: float = 0.0` field to `HardwareProfile` dataclass.
2. `detect_raw_profile()` now detects CUDA VRAM:
   ```python
   import torch
   if torch.cuda.is_available():
       props = torch.cuda.get_device_properties(0)
       gpu_vram_gb = props.total_memory / (1024 ** 3)
   ```
   Safe fallback to 0.0 when no GPU present. Never fails boot.
3. Batch size boost applied when `gpu_vram_gb > 0 and not profile.force_cpu`:
   - ≥ 16 GB VRAM → `max(batch_size, 8192)`
   - ≥ 8 GB VRAM → `max(batch_size, 4096)`
   - otherwise → `max(batch_size, 2048)`
4. `banner()` now shows `vram=X.XGB` when GPU is detected.

**Test safety:** Existing tests use `monkeypatch` on `psutil.virtual_memory` but do NOT mock `torch.cuda`, so in CI (no GPU) `gpu_vram_gb = 0.0` and no batch_size boost occurs — all existing assertions pass unchanged.

## W-1: Wire `run_wager2025_gaps()` into Stage 3 Pipeline

**Motivation:** `wager2025_addons.py::run_wager2025_gaps()` contains a complete auto-runner for all 10 Wager (2025) audit gap estimators. All estimator modules were implemented and individually tested, but the runner was **never called** — it was dead code during a default `sparc run`.

**Changes:** `sparc/run/v2_bayesian_causal.py` — inserted after NUTS block (~line 299), before `return`:

```python
# ---- Wager (2025) gap analysis (Stage 3, strictly additive) ----
wager2025_summary = None
try:
    from sparc.run.wager2025_addons import run_wager2025_gaps as _run_wager
    from sparc.causal.dag_definition import dag_to_networkx, get_node_roles
    _G = dag_to_networkx(dag_def)
    _roles = get_node_roles(_G)
    wager2025_summary = _run_wager(
        data=data, config=config, dag_def=dag_def,
        graph=_G, roles=_roles,
        output_dir=str(output_dir / "wager2025"),
        nuts_results=nuts_results,
    )
    logger.info("Wager 2025 gap analysis complete.")
except Exception as _exc:
    logger.warning("Wager 2025 gap analysis skipped: %s", _exc)
```

The `return` dict is extended with `"wager2025_summary": wager2025_summary`.

**Note:** Backlog erroneously listed import path as `sparc.causal.utils`. The actual module is `sparc.causal.dag_definition` (confirmed by reading the file).

**Safety:** The outer `try/except` guards against any import failure. Every individual gap inside `run_wager2025_gaps` is also wrapped in `try/except`. This call is strictly additive — it can never abort Stage 3.

## CU-9 and CU-10 Task Formalization

**Context:** Two GPU acceleration tasks were scoped today and added to `docs/research/backlog.md` as medium-complexity items following the completed CUDA-1/2/3 series.

### CU-9 — CUDA Graph capture for the inner epoch step

**Core constraint identified:** CUDA Graphs require perfectly static tensor shapes across all replayed invocations. The current training loop has three shape-variable sites:
1. Last minibatch remainder (N mod batch_size rows)
2. `_remap_indices_to_local` output shape (already `(B, K)` after E1-torch, but B varies on the last batch)
3. JEPA `spatial_patch_mask` derived from `b_coords`

**Solution approach:** A `_make_static_batch()` helper pads every batch to exactly `batch_size` rows (repeating the last element), returns a `valid_mask: torch.BoolTensor`, and passes it into `sparc_joint_loss` where padded rows contribute zero to all per-point loss terms. The graph captures only the static inner region (surrogates → meta-learner → loss). EWC and OT penalties remain outside the graph boundary (they use `.item()` and Python conditionals). `torch.cuda.make_graphed_callables` is gated behind `device.type == "cuda"` — zero change on CPU/MPS.

**Files:** `sparc/run/v2_neural_training.py` (padding helper, graph capture per fold + retrain), `sparc/training/loss.py` (`valid_mask` param on `sparc_joint_loss`).

**Dependencies confirmed:** E-Perf-A (torch.compile, done), CUDA-2 (AMP, done). Does not require CU-10.

### CU-10 — Multi-GPU DDP (DistributedDataParallel) training

**Four non-trivial changes identified:**
1. **Process launch:** `torch.multiprocessing.spawn` from `sparc/__main__.py` via a `--n_gpus N` CLI flag
2. **Model wrapping:** All 5 models (SPARCMetaLearner, ProcessRateNet, SourceTermNet, 3 surrogates) wrapped in `DistributedDataParallel`; `ema_trunk` explicitly NOT wrapped (not in gradient path)
3. **EWC/OT penalty sync:** `dist.all_reduce(penalty_scalar, ReduceOp.AVG)` before adding to `total_loss`; otherwise penalty magnitude halves on 2-GPU run
4. **Distributed spatial sampler:** `DistributedSpatialSampler` slices every W-th batch from `spatial_minibatch_sampler` output, preserving geographic locality per rank

**Key regression risks documented:** `model.module` unwrapping needed at ~12 attribute-access sites (Fisher extraction, gate weight save, SWA, export); rank-0-only guards on all artifact writes; `compute_fisher_matrix` in `ewc.py` needs rank-aware data loader sharding + `dist.all_reduce` of Fisher tensors.

**Out of scope for medium complexity:** Multi-node (torchrun/SLURM), model parallelism, DDP inside capacity sweep CMA-ES.

**Files:** `sparc/run/v2_neural_training.py`, `sparc/__main__.py`, `sparc/config/hardware_profile.py`, `sparc/training/ewc.py`.
