## Grounded Directions

### 1. Vectorize `_remap_indices_to_local` — Replace Python `for` with numpy fancy indexing

**Gap:** `sparc/run/v2_neural_training.py`, line 213.

The current implementation:
```python
local_map = -np.ones(global_idx.max() + 1, dtype=np.int64)
for local_i, global_i in enumerate(batch_idx):
    if global_i < len(local_map):
        local_map[global_i] = local_i
```
This is called 3 times per batch (KNN, cardinal, GWRF-KNN), across all batches, in all three training loops (CV fold, full retrain, SWA). For a 3 000-point dataset with batch size 256, that is 3 × 12 batches × 100 epochs × 3 loops = ~11 000 invocations, each iterating 256 times in Python.

**Method:** numpy fancy-index assignment is vectorized C and ~50× faster than a Python enumerate loop.

**Implementation sketch:**
```python
def _remap_indices_to_local(
    global_idx: np.ndarray,
    batch_idx: np.ndarray,
    neighbor_tensor: torch.Tensor,
) -> torch.Tensor:
    size = global_idx.max() + 1 if len(global_idx) else 0
    local_map = np.full(size, -1, dtype=np.int64)
    local_map[batch_idx] = np.arange(len(batch_idx))  # ← single vectorized write

    nb = neighbor_tensor.cpu().numpy()
    remapped = np.full_like(nb, -1)
    valid = (nb >= 0) & (nb < size)
    remapped[valid] = local_map[nb[valid]]
    return torch.tensor(remapped, dtype=torch.long, device=neighbor_tensor.device)
```

### 3. Vectorize `calculate_fold_spatial_autocorr` Moran's I

**Gap:** `sparc/run/enhanced_spatial_cv.py`, lines 258–265.

The double Python for-loop:
```python
for i in range(n):
    for j in range(1, k_neighbors+1):
        neighbor_idx = indices[i, j]
        weight = 1.0 / k_neighbors
        total_similarity += weight * y_centered[i] * y_centered[neighbor_idx]
        total_weight += weight
```
For each fold diagnostics call (N=2000, K=8) this runs 16 000 Python iterations. The function is called after every fold for every model — with 5 folds × 4 models = 20 calls per run.

**Method:** numpy vectorized cross-product via fancy indexing. The row-sum equivalent is a single matrix-element gather operation:

**Implementation sketch:**
```python
def calculate_fold_spatial_autocorr(residuals, coords, threshold=1000):
    if len(residuals) < 10:
        return 0.0
    from sklearn.neighbors import NearestNeighbors
    k_neighbors = min(8, len(residuals) - 1)
    if k_neighbors < 1:
        return 0.0
    nbrs = NearestNeighbors(n_neighbors=k_neighbors + 1).fit(coords)
    _, indices = nbrs.kneighbors(coords)
    n = len(residuals)
    y_mean = residuals.mean()
    yc = residuals - y_mean
    # Vectorized: cross-products for all k neighbors at once
    # indices[:,1:] shape (N, K), skip self at col 0
    yc_nb = yc[indices[:, 1:]]          # (N, K)
    cross = (yc[:, None] * yc_nb).sum()  # scalar
    morans_i = (n / (k_neighbors * n)) * (cross / (np.sum(yc**2) + 1e-12))
    return float(morans_i)
```

### 5. `predict_with_uncertainty` — `torch.inference_mode` + Eval Restoration

**Gap:** `sparc/models/neural_meta.py` — `predict_with_uncertainty` method.

Current:
```python
def predict_with_uncertainty(self, *args, n_samples=100, **kwargs):
    self.train()   # activate dropout
    predictions = []
    with torch.no_grad():
        for _ in range(n_samples):
            T_pred, _, _ = self.forward(*args, **kwargs)
            predictions.append(T_pred)
    predictions = torch.stack(predictions, dim=0)
    return predictions.mean(dim=0), predictions.std(dim=0)
```

Two issues:
1. `torch.no_grad()` disables gradient tracking but does not disable gradient tape construction in all PyTorch versions. `torch.inference_mode()` is strictly faster (skips view tracking, faster tensor allocation).
2. `self.train()` is called to activate dropout but the model's prior eval/train state is never restored after the call — any downstream call that expects eval mode gets unexpected stochasticity.

**Method:** Use `torch.inference_mode()` (PyTorch 1.9+, always available in SPARC's torch version); save and restore the model's training state.

**Implementation sketch:**
```python
def predict_with_uncertainty(self, *args, n_samples=100, **kwargs):
    was_training = self.training
    self.train()  # activate dropout for MC
    predictions = []
    with torch.inference_mode():
        for _ in range(n_samples):
            T_pred, _, _ = self.forward(*args, **kwargs)
            predictions.append(T_pred)
    if not was_training:
        self.eval()  # restore prior state
    predictions = torch.stack(predictions, dim=0)
    return predictions.mean(dim=0), predictions.std(dim=0)
```

Files touched: `sparc/models/neural_meta.py` — `predict_with_uncertainty` body (~8 lines).
**Success criterion:** Existing MC Dropout tests pass with identical statistics (same RNG seed → same predictions); `model.training` is False after calling `predict_with_uncertainty(model.eval())`.
**Risk:** None — behavioral equivalence guaranteed; `inference_mode` is strictly faster than `no_grad`.

## Blue-Sky Ideas

### A. `torch.compile` the Epoch Step Function
**Source field:** PyTorch 2.0 compilation (Ansel et al. 2024, "PyTorch 2: Faster Machine Learning through Dynamic Python Bytecode Transformation")

**Core idea:** The inner epoch loop dispatches 3 sequential surrogate forwards + SPARCMetaLearner + PDE loss, each as separate Python calls. `torch.compile(mode="reduce-overhead")` on a wrapped `_epoch_step(batch_dict) -> loss` function would: (1) fuse GELU/LayerNorm kernel pairs across the surrogate and meta-learner, (2) eliminate the Python dispatch cost on each `nn.Module.forward()`, (3) produce a single GPU kernel for the `cat → fusion → regression_head` sequence. The blocker is `_remap_indices_to_local` — it contains numpy operations that break `torch.compile`'s graph capture. **Gap E1's vectorization is a necessary prerequisite**: once `local_map[batch_idx] = np.arange(...)` is the only numpy call, it can be replaced with a pure-torch version (`torch.zeros(...).scatter_`) and the entire epoch step becomes compile-safe.

**Relevant SPARC modules:** `sparc/run/v2_neural_training.py` (epoch loop closures), `sparc/models/neural_meta.py` (SPARCMetaLearner), `sparc/run/v2_neural_training.py:_forward_surrogates`.
**Potential payoff:** 1.5–3× epoch throughput on CPU; 3–5× on MPS/CUDA (kernel fusion savings). Particularly valuable in the SWA phase and JEPA pretrain loop.

---

### B. Precomputed Sparse Laplacian Matrix for `compute_pde_loss`
**Source field:** Sparse linear algebra / finite-difference operators (LeVeque 2007, "Finite Difference Methods for Ordinary and Partial Differential Equations")

**Core idea:** `_build_cardinal_neighbors` produces a `(N, 4)` dense cardinal index array. Inside `compute_pde_loss`, the Laplacian `∇²T` is computed via explicit index-gather from the neighbor array — four separate `T_pred[neighbor_idx[:, k]]` gathers for N/S/E/W. For large grids (N > 5 000) this pattern generates 4 uncoalesced scatter-gather operations per Laplacian evaluation. An equivalent formulation: precompute the sparse Laplacian matrix `L ∈ R^(N×N)` once (it only changes when coordinates change), then compute `lap_T = L @ T_pred` as a single `torch.sparse.mm`. The matrix is stored as a `torch.sparse_coo_tensor` with at most `4N` non-zeros and does not change across epochs. The current `_build_cardinal_neighbors` already returns the same structure every time for the same coordinate set.

**Relevant SPARC modules:** `sparc/physics/pde_operators.py` (`laplacian()`), `sparc/physics/pde_loss.py` (`compute_pde_loss`), `sparc/run/v2_neural_training.py:_build_cardinal_neighbors`.
**Potential payoff:** Single precomputed sparse matmul replaces 4 per-epoch gathers; GPU-compatible (`torch.sparse` is CUDA-supported); the sparse matrix can be precomputed once in `_prepare_tensors` and reused across all epochs (same cardinal structure = same `L`). Particularly valuable on GPU/MPS where batched sparse matmul is highly optimized.

## Implementation Note — E-Perf-B (precomputed sparse Laplacian)

- **Files changed:** `sparc/physics/pde_operators.py`, `sparc/physics/pde_loss.py`, `sparc/training/loss.py`, `sparc/run/v2_neural_training.py`
- **What was done:** Added `build_sparse_laplacian(cardinal_idx, h)` to `pde_operators.py` — builds a `torch.sparse_coo_tensor` of shape `(N, N)` with `L[i,i] = -4/h_i²` and `L[i,j] = +1/h_i²` for all valid cardinal neighbors, using vectorised scatter (no Python loop over N). - **What was learned:** Sign convention: the standard graph Laplacian `L = D − A` gives `(L@f)[i] = 4f_i − Σf_j`, which is the **negative** of the usual PDE Laplacian `∇²f = Σf_j − 4f_i`. The sparse path only activates for full-N evaluation (when `T_pred.shape[0] == sparse_L.shape[0]`); batch training falls back to the existing 4-gather path since the training loop uses batch-local remapped cardinal indices, not global ones.

  - `sparc/physics/pde_operators.py`: `build_sheaf_laplacian(knn_idx, stalk_dim=2, restriction_maps=None)` — builds sparse coboundary operator δ⁰ : C⁰(ℱ) → C¹(ℱ) for a KNN spatial graph. Each stalk ℝ^d (d=2 for fine+coarse scales). Identity restriction maps by default; custom (E, d, d) `restriction_maps` supported. Returns `(E·d, N·d)` sparse_coo_tensor. Validated: δ⁰ f = 0 for constant sections (cohomology property).
  - `sparc/physics/pde_loss.py`: Added `PDELossWeights.sheaf = 0.03`. Added Term 11 `pde_sheaf` in `compute_pde_loss` — coarse scale = KNN average of T_pred (4 cardinal neighbors), stalk = [T_fine, T_coarse]; loss = ||δ⁰ f||² normalised; activated at `pde_epoch ≥ 20` (latest activation schedule); `sheaf_delta` parameter is optional (term = 0 when absent). Added `sheaf_delta` param to signature.
  - `sparc/run/v2_neural_training.py`: `_prepare_tensors` builds `sheaf_delta` from `tensors["knn_index"]` via `build_sheaf_laplacian`; passed to all 3 `compute_pde_loss` call sites (CV loop, full-retrain loop, SWA loop).
- **Tests:** 14/14 pass (4.47s). Combined with all other blue-sky tests: 72/72 pass.
- **Design decisions:**
  - Used KNN-smoothed T as the "coarse scale" proxy — avoids requiring a second multi-resolution forward pass. T_coarse[i] = mean(T[neighbors]). This is a 1-hop local average, which approximates what block-level aggregation would produce for a spatially smooth field.
  - Returned δ⁰ (coboundary operator) rather than full Sheaf Laplacian L = (δ⁰)ᵀ δ⁰ — because the loss ||δ⁰ f||² is computed via sparse.mm(δ⁰, f), which is one sparse-dense product rather than a sparse-sparse product for L.
  - Stage activation at pde_epoch≥20 ensures the supervised loss dominates in early training; sheaf term ramps in after energy_balance and directional terms are stable.
  - `_normalize_residual` applied to scalar sheaf_loss to keep scale consistent with other terms.
