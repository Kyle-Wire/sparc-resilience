### Known Architecture Debt (not addressed this session)

1. **`_exec_cv_fold` is still a 1600-line god function.** `FoldTrainer._run_cv_fold_main_loop()` wraps it. The main epoch loop needs to be extracted into `MainFoldPhase.run()` and `SWAPhase.run()` before `_exec_cv_fold` can be fully retired. This requires threading `FoldModels` through `_exec_cv_fold` or extracting the body — a separate large refactor.

2. **`FoldTrainer.run()` is still redundant.** Because `_exec_cv_fold` rebuilds all models internally, the calls to `build_models()`, `pretrain_surrogates()`, `pretrain_process_rate()` in `run()` do work that is then immediately re-done. The fix requires modifying `_exec_cv_fold` to accept pre-built models (a `fold_models` parameter) or extracting the epoch body. Tracked in backlog.

3. **`zero_shot.py` still uses tempfile.** Only `few_shot.py` was updated to use `TrunkLoader`. `zero_shot.py` should also be updated in the next session.

## Grounded Directions

### Direction A — Complete the `_exec_cv_fold` decomposition
**Gap:** `FoldTrainer.run()` calls `_run_cv_fold_main_loop()` which still delegates to `_exec_cv_fold`. Pre-training phases in `run()` are no-ops (their work is immediately redone). The god function remains at ~1600 lines.
**Roadmap ref:** Phase 2.3 — Training orchestration seams (SPARC_Future_Roadmap.md)
**Method:** Introduce `fold_models: FoldModels | None = None` parameter to `_exec_cv_fold`. When provided, skip the model-building and pre-training phases. `FoldTrainer.run()` then passes `self._models` to avoid redundant work.
**Minimal implementation:** 
  1. Add `fold_models=None` to `_exec_cv_fold` signature
  2. Guard the model-building block: `if fold_models is None: ... else: use fold_models`
  3. Update `FoldTrainer._run_cv_fold_main_loop()` to pass `self._models`

### Direction B — Complete TrunkLoader wiring in `zero_shot.py`
**Gap:** `sparc/inference/zero_shot.py` uses the same tempfile anti-pattern. `TrunkLoader` now exists but is not yet imported there.
**Roadmap ref:** Phase 4.1 — Zero/few-shot inference (SPARC_Future_Roadmap.md)
**Method:** Mirror the `few_shot.py` update — replace the tempfile block with `TrunkLoader.from_registry()`.
**Minimal implementation:** Same 10-line change as `few_shot.py`.

### Direction C — Lazy `HARDWARE_CONFIG` population in `cv_engine.py`
**Gap:** `cv_engine.py` imports `enhanced_spatial_cv.py` and uses `HARDWARE_CONFIG`. Now that the module-level call is removed, `HARDWARE_CONFIG` is an empty dict at import time. `SpatialCVEngine` should call `refresh_hardware_config()` if `HARDWARE_CONFIG` is empty.
**Roadmap ref:** Phase 1.2 — Engine layer clean interfaces
**Minimal implementation:** In `SpatialCVEngine.__init__()`, check `if not HARDWARE_CONFIG: refresh_hardware_config(verbose=False)`.

## Blue-Sky Ideas

### Idea 1 — `FoldState` as a serializable "fold recipe"
Now that `FoldState` is in its own module with clean dataclass fields, it could be JSON-serializable for experiment reproducibility. A `FoldState.to_json()` / `FoldState.from_json()` pair would let the SPARC server persist and replay any fold exactly — enabling the "resume from checkpoint" and "retrain fold N only" features that are currently blocked by the opaque dict pattern.
**Adjacent field:** MLflow / DVC experiment tracking
**SPARC connection:** `sparc/run/fold_state.py` — now has clear field boundaries
**Payoff:** Enables fold-level experiment reproducibility, comparison, and incremental retraining without running the full pipeline.

### Idea 2 — `TrunkLoader` as a capability registry entry point
`TrunkLoader.from_registry()` currently queries `CityRegistry` for a climate-zone match. This could be extended to use a capability vector (e.g., physics feature overlap, coordinate extent) rather than just climate zone, implementing a form of nearest-neighbor trunk retrieval. The K-medoids coreset centroids already stored in `CityRegistry` are natural prototype vectors for this comparison.
**Adjacent field:** Case-based reasoning / retrieval-augmented generation
**SPARC connection:** `sparc/inference/trunk.py`, `sparc/registry/city_registry.py`
**Payoff:** Smarter trunk initialization for new cities, potentially improving zero-shot calibration in climatologically diverse datasets.
