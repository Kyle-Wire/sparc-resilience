## Codebase State

### What was found

**MC³ (`sparc/causal/mc3.py`):**
- `run_mc3()` is fully implemented with parallel tempering, incremental BGe scoring, and physics-informed prior.
- Default temperature ladder is `[1.0, 0.5, 0.25, 0.1]` (factor-of-2 gaps).
- `_propose()` silently returns empty `affected` list on cyclic proposals — these are skipped without incrementing any counter, making the acceptance denominator `n_iter` misleading.
- `PhysicsInformedGraphPrior.log_prior()` applies `penalty_acyclic=1.0` to every included edge on top of the log-probability of the edge existing. This doubly penalizes edges.

**`sparc/config/causal_defaults.py`:**
- `mc3.n_iterations: 10000` — the canonical default is 5× too low for p ≥ 5 nodes.
- `nuts.n_samples: 2000`, `nuts.n_warmup: 500`, `nuts.target_accept_rate: 0.85`.
- `nuts.n_chains: 2` is defined but **never consumed** — `run_nuts()` has no multi-chain support.

**`sparc/run/v2_bayesian_causal.py` orchestrator defaults:**
- Falls back to `n_samples=6000`, `n_warmup=600`, `target_accept=0.65` when project.yml omits the causal block entirely.  
- This contradicts `causal_defaults.py` (2000 / 500 / 0.85). Inconsistency creates unpredictable behavior based purely on whether `causal:` appears in project.yml.

**NUTS (`sparc/causal/nuts.py`) — `_dual_average_step_size()`:**
- `theta = theta0.clone()` at top of loop; **theta is never updated inside the dual-averaging loop**.
- Every single-step leapfrog acceptance is measured from the same starting point (β = 0 by default).
- The adapted step size represents the curvature only at the initialization, not across the posterior.
- After mass matrix adaptation, re-adaptation also runs from a fixed point (the end of warmup transitions, not updated per dual-averaging step).
- **This is a confirmed implementation deviation from Hoffman & Gelman (2014) Algorithm 6**, which updates position after each NUTS transition during dual averaging.

**NUTS warmup phase split:**
- `n_adapt = max(50, n_warmup // 5)` → 100 dual-averaging steps with `n_warmup=500`.
- 100 steps is far below the minimum for dual-averaging convergence (~500 is standard; Stan uses ≥ 500 post-mass-matrix).
- After mass matrix: `min(n_adapt, 500) = 100` re-adaptation steps — still insufficient.

**Sign constraint barrier:**
- `barrier_scale = 10.0` (hardcoded in `v2_bayesian_causal.py`).
- `softplus(b * 10)` creates near-discontinuous gradient at β ≈ 0 — steep cliff that NUTS leapfrog mis-handles, causing excessive U-turns and divergences when chains initialize near zero.

**Hardware-driven thinning:**
- `thin = _NUTS_THIN` from `HardwareProfile`.
- On `eco` preset or any custom `nuts_thin=8` setting: 2000 posterior draws thinned to 250 stored samples.
- ESS floor in the diagnostics is `max(100, min(400, 0.25 * n_samples))`. With 250 stored samples the floor is `max(100, 62.5) = 100`. So ESS ≥ 100 is required from only 250 samples — that's a 40% effective-sample ratio, which a poorly-mixed single-chain NUTS with bad step size cannot reliably achieve.

## Grounded Directions

### Direction 1 — Fix `_dual_average_step_size` theta-update bug (NUTS-CRIT-1)

**Gap:** `_dual_average_step_size()` in `nuts.py` runs `n_adapt` single-step leapfrogs all from the same frozen `theta0`. The dual-averaging algorithm requires updating the sampler position after each accepted step so the step size is calibrated to the posterior geometry, not just the initialization. Algorithm 6 in Hoffman & Gelman (2014) explicitly propagates θ.

**Roadmap ref:** Phase 5 — Causal Inference Leadership (SPARC_Future_Roadmap.md §Phase 5 "NUTS posterior sampling").

**Academic method:** Hoffman, M.D. & Gelman, A. (2014). "The No-U-Turn Sampler: Adaptively Setting Path Lengths in Hamiltonian Monte Carlo." JMLR 15:1593–1623. Algorithm 6 (dual averaging) — the position θ is advanced by a single NUTS step at each adaptation iteration.

**Minimal implementation:**
- In `_dual_average_step_size()`: after computing `alpha` from the leapfrog acceptance, apply MH acceptance to update `theta = theta_prime if rng.random() < alpha else theta`.
- One line added inside the for-loop after `alpha = ...`.
- File: `sparc/causal/nuts.py`, `_dual_average_step_size()` function, ~line 460.
- No signature changes. Regression-safe: pure improvement to internal adaptation dynamics.

### Direction 2 — Raise MC³ default iterations and add density-adaptive minimum (MC3-CRIT-1)

**Gap:** `causal_defaults.py` sets `n_iterations: 10000`. With p=7 nodes and 2–3% acceptance rate, only ~200–300 unique DAG states are ever accepted — insufficient for stable edge inclusion posterior.  The standard recommendation (Madigan & York 1995; Friedman & Koller 2003) for BGe MC³ over p variables is `O(p² × 1000)` iterations minimum; for p=7 that's ~50K. For p=10+, 100K.

**Roadmap ref:** Phase 5 — Causal Inference Leadership.

**Academic method:** Madigan, D. & York, J. (1995). "Bayesian Graphical Models for Discrete Data." ISR 63(2):215–232. (canonical MC³ iteration budget); Friedman, N. & Koller, D. (2003). "Being Bayesian About Network Structure." Machine Learning 50:95–125. (p-scaled budgets).

**Minimal implementation:**
- `causal_defaults.py`: change `n_iterations: 10000` → `50000`.
- Add `min_iterations: 20000` to mc3 block (already has the parameter in `run_mc3()` but not in defaults).
- Add a note in `run_mc3()` to log a WARNING when `n_iter < p * p * 1000` at call time.
- Files: `sparc/config/causal_defaults.py` line 29; `sparc/causal/mc3.py` top of `run_mc3()`.

### Direction 3 — Reduce sign-constraint barrier scale and add warm initialization (NUTS-HIGH-1)

**Gap:** `barrier_scale=10.0` creates `softplus(β × 10)` which approximates a step function at β=0. NUTS leapfrog sees a near-zero gradient for β > 0.3 and a very large gradient for β < -0.3, causing the integrator to overshoot into the constrained region and bounce back. This produces many short trajectories (early U-turns) and inflates autocorrelation.

**Roadmap ref:** Phase 5 — "NUTS posterior sampling."

**Academic method:** Betancourt, M. (2017). "A Conceptual Introduction to Hamiltonian Monte Carlo." arXiv:1701.02434. §6: barriers should be smooth and scaled to the posterior width. Gelman, A. et al. (2020). "Bayesian Workflow." arXiv:2011.01808. §8: soft prior constraints preferred over hard barriers.

**Minimal implementation:**
- Change `barrier_scale = 10.0` → `barrier_scale = 2.0` in `_run_nuts_sampling()` (`v2_bayesian_causal.py` line ~760). This softens the constraint to `softplus(β × 2)`, which still heavily penalizes wrong-sign betas but transitions smoothly over a range of ~0.5–1.0 instead of 0.1.
- Add a `barrier_scale` parameter to `nuts_cfg` (default `2.0`) so it is tunable from config.
- File: `sparc/run/v2_bayesian_causal.py`, `log_prob` closure.

### Direction 4 — Increase n_adapt budget and add iterating mass matrix windows (NUTS-CRIT-2 + NUTS-HIGH-2)

**Gap:** `n_adapt = max(50, n_warmup // 5)` yields only 100 steps for dual averaging when `n_warmup=500`. Empirically, dual averaging requires ≥ 500 steps to converge. Stan uses a three-phase warmup: initial step size (75 steps) → iterated mass matrix windows (25/50/100/200... steps each) → final step size (50 steps), with total warmup ≥ 1000 recommended.

**Roadmap ref:** Phase 5 — Causal Inference Leadership.

**Academic method:** Betancourt (2017) §5; Stan Reference Manual §15.2 (windowed adaptation). The iterating-window design ensures mass matrix estimate is refreshed as the chain moves toward the posterior.

**Minimal implementation (two sub-fixes):**
1. In `run_nuts()`: change `n_adapt = max(50, n_warmup // 5)` → `n_adapt = max(200, n_warmup // 2)`. This allocates 50% of warmup to step-size adaptation (300 out of 600) rather than 20%.
2. In the mass-matrix re-adaptation: change `min(n_adapt, 500)` → `min(max(200, n_adapt), 500)` to ensure at least 200 re-adaptation steps after mass matrix.
3. (Optional medium complexity): Implement Stan-style doubling windows for mass matrix: collect warmup samples in windows of size [25, 50, 100, 200] and refresh the mass matrix at each window boundary.
- File: `sparc/causal/nuts.py`, `run_nuts()` lines ~608 and ~660.

### Direction 5 — Denser temperature ladder and swap-rate diagnostic for MC³ (MC3-HIGH-1)

**Gap:** Temperature ladder [1.0, 0.5, 0.25, 0.1] has factor-of-2 gaps. For DAG posteriors (discrete, multi-modal), swap acceptance rate is approximately `exp(−(β_i − β_j) × ΔH)` where ΔH is the score gap between adjacent chain modes. Factor-of-2 gaps produce near-zero swap rates when chains are at different modes. The standard recommendation (Geyer 1991) is to tune temperature ladders so each adjacent pair swaps at ~25–40%.

**Roadmap ref:** Phase 5 — Causal Inference Leadership.

**Academic method:** Geyer, C.J. (1991). "Markov chain Monte Carlo maximum likelihood." Proceedings of the 23rd Symposium on the Interface; Earl & Deem (2005) "Parallel tempering: Theory, applications, and new perspectives." Phys. Chem. Chem. Phys. 7:3910–3916.

**Minimal implementation:**
- Change default ladder from `[1.0, 0.5, 0.25, 0.1]` to `[1.0, 0.75, 0.55, 0.4, 0.28, 0.2, 0.1]` (geometric spacing, factor ~1.37).
- Add `n_chains=7` as the new default to use the denser ladder.
- Add swap-rate logging per adjacent chain pair in `run_mc3()` (track accepted swaps per pair, log at end).
- File: `sparc/config/causal_defaults.py` mc3 block; `sparc/causal/mc3.py` `run_mc3()` swap tracking.

## Blue-Sky Ideas

### Idea 1 — Riemannian HMC for Correlated Treatment Posteriors (NUTS geometry)
**Adjacent field:** Information geometry / Riemannian manifold Monte Carlo (Girolami & Calderhead 2011).
**Connection to SPARC:** NUTS uses a diagonal mass matrix which cannot capture correlations between β coefficients. When treatments are spatially co-located (e.g., canopy and impervious surfaces are anticorrelated by land-use), the posterior of β is a banana-shaped ridge in treatment space. A dense or low-rank mass matrix captures this curvature, reducing autocorrelation by 10–100× vs diagonal. The SPARC treatment standardization step already has the cross-treatment covariance (X_raw covariance matrix) which is the natural empirical Fisher at the likelihood mode — exactly the right seed for a full mass matrix.
**Potential payoff:** ESS×5–20 improvement without changing the sampler algorithm; implementation requires only replacing `inv_mass_diag` (1D tensor) with an off-diagonal `inv_mass_chol` (dense Cholesky) in `_leapfrog` and `_kinetic_energy`.
**Existing SPARC infrastructure:** `X_means`, `X_stds`, `X_raw` covariance already computed in `_run_nuts_sampling()`; mass matrix scaffold already accepts optional `inv_mass_diag`.

### Idea 2 — Stein Variational Gradient Descent as MC³ Warm-Start
**Adjacent field:** Stein variational inference (Liu & Wang 2016).
**Connection to SPARC:** MC³ initializes from the empty DAG. SVGD over a differentiable BGe relaxation (continuous DAG score via Zheng et al. 2018 NOTEARS) can rapidly find a diverse set of high-score DAG candidates in a few hundred gradient steps. These become the warm-start points for the parallel chains, replacing random initialization. The NOTEARS adjacency parameterization `W = σ(θ)` already has a PyTorch-differentiable BGe analog in the existing `BGeSuffStats` scatter matrix.
**Potential payoff:** Warm-started MC³ chains begin near high-posterior regions, potentially raising acceptance rate from 2–3% to 15–30% immediately.
**Existing SPARC infrastructure:** `BGeSuffStats` + torch backend already in `mc3.py`; NOTEARS DAGness constraint `h(W) = tr(e^{W∘W}) - p = 0` can be used as a soft penalty for differentiable pre-search.
