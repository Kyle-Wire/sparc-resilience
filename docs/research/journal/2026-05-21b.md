### Secondary gap — NUTS default budgets too high for interactive use

`_run_nuts_sampling()`: `n_samples=15_000, n_warmup=1_000` (hard-coded defaults).  
`_run_per_edge_nuts_sampling()`: `per_edge_n_samples=3_000, per_edge_n_warmup=500`.

With 8 CPU threads and no GPU, these defaults produce:
- Main NUTS: ~7–9 min
- Per-edge NUTS (7 edges × 3 k samples): ~6–9 min
- **Total NUTS alone: ~15–18 min — silently**

Note: `project.yml` had `nuts.n_samples: 2000` overriding the default, so the
practical impact for this project was lower than the raw default suggests.

### Latent bug — AttributeError in DML econml fallback

In `counterfactual_engine.py::_fit_edge_dml()`, the econml exception handler
called `self._fit_edge_dml_sklearn(...)` where `self` was the `CausalValidator`
instance passed via `CounterfactualEngine._fit_edge_dml(validator_self, ...)`.
`CausalValidator` does not inherit `CounterfactualEngine`, so `AttributeError`
would replace the econml error if econml raised. Silent data-quality regression
risk on any machine missing the econml Cython extension.

### HGB nuisance model settings — over-engineered for causal nuisance estimation

`_fit_edge_dml` configured `HGB(max_iter=200, max_depth=4)` for nuisance
regression on a 7-node DAG with 6 predictors. `max_iter=100, max_depth=3`
is standard for causal nuisance estimation (Chernozhukov et al. 2018) and
halves per-edge DML time (~30 s → ~15 s on this dataset).

### DML suitability for 54 k rows

`LinearDML` with HGB nuisances on 54,701 rows × 5-fold CV × 2 models per
edge × ~7 edges ≈ **3–5 min total** — well within acceptable range. DML is not
"too extreme" for this dataset. The perceived issue was purely the silent
execution, not computational infeasibility.

## Grounded Directions

### G-1: Spatial block CV for DML folds (Phase 2.3 gap)

**Gap:** `counterfactual_engine.py::_fit_edge_dml()` uses K-Fold with
`spatial_block_size=None` by default → random folds that ignore spatial
autocorrelation. With Providence data at EPSG:26919, a block size ≈ the
Matérn effective range (already computed in Stage 0) would produce
decorrelated train/test splits.

**Roadmap ref:** Phase 2 — *Spatial Generalization* / enhanced\_spatial\_cv

**Academic method:** Valavi et al. (2019) "blockCV" — spatial block cross-
validation with range-calibrated block sizes. SPARC Stage 0 already computes
the Matérn ρ parameter stored as `effective_range_matrix` in the artifact
store; `_load_kernel_field("effective_range")` provides it.

**Minimal implementation:**
1. In `_fit_edge_dml`, load `effective_range_matrix` from artifact store (one
   `_get_store().read_struct("0", "effective_range_matrix")` call).
2. Set `spatial_block_size = np.percentile(ranges, 10)` (MER heuristic).
3. Pass `spatial_block_size` to `SpatialBlockKFold` (already wired in
   `enhanced_spatial_cv.py`).

**Files touched:** `sparc/causal/counterfactual_engine.py` (~15 lines),
`sparc/run/enhanced_spatial_cv.py` (no changes needed — already supports it).

### G-2: Per-edge NUTS ESS convergence check + adaptive budget (Phase 3.1 gap)

**Gap:** `_run_per_edge_nuts_sampling()` runs a fixed budget
(`per_edge_n_samples`) regardless of chain ESS. For edges with high
autocorrelation (e.g., collinear features like NDVI ↔ Pct\_Canopy), the
budget may be insufficient even at 1,500 samples.

**Roadmap ref:** Phase 3 — *Calibrated Uncertainty*

**Academic method:** Hoffman & Gelman (2014) NUTS adaptation + ESS-adaptive
stopping (Vehtari et al. 2021 "Rank-normalization, folding, and localization
for R-hat"). The ESS floor is already computed in `run_nuts()` via
`_compute_ess_bulk()`.

**Minimal implementation:**
Add to `_run_per_edge_nuts_sampling()`:
```python
ess = float(np.mean([v.ess for v in res.diagnostics]))
if ess < 200 and n_samples < 4000:
    # Double budget and re-run once
    res = run_nuts(..., n_samples=min(n_samples * 2, 4000), ...)
```
This doubles the budget at most once, adds ~5 s per problematic edge, and
avoids misleading low-ESS posteriors entering `scenario_coefficients.json`.

**Files touched:** `sparc/run/v2_bayesian_causal.py` (~20 lines in
`_run_per_edge_nuts_sampling`).

### G-3: Per-edge DML → per-edge NUTS consistency check (Phase 3.2 gap)

**Gap:** `validator.fit()` produces a frequentist DML point estimate per edge.
`_run_per_edge_nuts_sampling()` produces a Bayesian posterior per edge. These
two estimates are never compared — a sign discordance (e.g., DML β < 0,
NUTS posterior mean > 0) would silently produce incoherent scenario outputs.

**Roadmap ref:** Phase 3 — *Causal Stack Integration*

**Academic method:** Dawid (1982) coherence checking; practical implementation:
compute `P(sign discordance) = P(DML_coeff * NUTS_mean < 0)` and log a
`[WARN]` when probability exceeds 0.10.

**Minimal implementation:**
After `_run_per_edge_nuts_sampling()` returns, add a 10-line coherence check
in `run_bayesian_causal()` that reads the DML coefficients from the artifact
store and computes the sign probability for each edge. Write result to
`("3", "sign_coherence")` and emit a `[WARN]` if any edge has discordance
probability > 0.10.

**Files touched:** `sparc/run/v2_bayesian_causal.py` (~35 lines),
`sparc/run/causal_validation.py` (~5 lines for reading DML coefficients
from artifact store before calling `run_bayesian_causal()`).

## Blue-Sky Ideas

### B-1: Causal CATE surface via Spatial GP posterior conditioned on NUTS β

**Adjacent field:** Gaussian Process regression conditioned on NUTS posterior
samples (Kennedy & O'Hagan 2001; Stein 2012).

**SPARC connection:** Currently, `spatial_cate.py` uses `CausalForestDML`
(frequentist non-parametric). NUTS produces a full posterior `β ~ P(β|Y)` for
each edge. Each posterior draw of β defines a different CATE surface. A GP
posterior over CATE (conditioned on NUTS β draws) would produce *credible
interval maps* of treatment effects, not just point estimates — a unique
publishable output.

**Potential payoff:** First-class uncertainty quantification on spatial CATE
maps; natural extension of the existing `correlogram_matern_fit.py` Matérn
kernel into a spatial CATE posterior sampler.

**Existing infrastructure:** `sparc/causal/spatial_cate.py`,
`sparc/run/correlogram_matern_fit.py`, NUTS β posterior already stored as
`("3", "nuts_beta")`.

---

### B-2: Structural Causal Model (SCM) consistency scoring via do-calculus

**Adjacent field:** Pearl's do-calculus (Pearl 2000; Bareinboim & Pearl 2016)
applied to simulate interventions on the fitted DAG.

**SPARC connection:** Stage 3 already builds scenario\_coefficients.json for
intervention propagation. Using the full posterior DAG (from MC³ edge
inclusion probabilities, not just the median DAG) would produce *intervention
distributions* rather than point predictions — `P(Y | do(X=x))` with credible
intervals that account for DAG uncertainty.

**Potential payoff:** SPARC scenario outputs would carry proper uncertainty
from both coefficient posterior uncertainty (NUTS) *and* structural uncertainty
(MC³ edge posteriors) — a methodologically defensible causal claim suitable
for peer review.

**Existing infrastructure:** `sparc/causal/mc3.py` (edge inclusion probs),
`sparc/run/v2_bayesian_causal.py` (NUTS β posterior), Stage 3 `median_dag`
artifact.

## Implementation Note — S3-1 Spatial block CV for DML folds
- Files changed: `sparc/causal/counterfactual_engine.py` (lines 341–362, inside `fit()`)
- What was done: Added a 22-line auto-detection block after `spatial_block_size` is read from config. When `estimator == 'dml'` and the user has not set `causal.spatial_block_size`, the block calls `get_active_store()`, checks `.has("0", "effective_range_matrix")`, reads it via `.read_any()`, flattens all non-None values from `range_matrix`, and sets `spatial_block_size = np.percentile(range_values, 10)`. Logs an INFO line: "DML spatial block CV activated (block_size=<N>m from effective_range_matrix)". Falls back silently to random K-fold on any exception (artifact absent, store unavailable, etc.).
- Tests: `test_causal_stack.py` 10/10 passed; `test_causal_gaps_wager2025.py` 13/13 passed. `test_bayesian_cate.py` timed out at 60 s on NUTS warmup — pre-existing issue unrelated to this change (stack trace confirms timeout in `nuts.py::_build_tree`).
- What was learned: `effective_range_matrix["range_matrix"]` is a list-of-lists (not ndarray) with `None` for non-significant pairs; the `None` filter is required before calling `np.percentile`. The 10th-percentile heuristic is intentionally conservative (uses the shortest significant range) so that spatial folds are always separated by at least the minimum autocorrelation scale.

## Implementation Note — S3-3 DML–NUTS sign coherence check
